A static page over a local SQLite file. No backend, no build step, no network calls except the one CDN fetch for the SQLite engine.

activity_logs.db  (written by the agents)
      │
      │  File System Access handle, or a file input
      ▼
sql.js (SQLite compiled to WASM, loaded from CDN)
      │  SELECT * FROM logs ORDER BY timestamp DESC
      ▼
rows: plain objects, held in component state
      │
      ├─ filters + drill scope  → rows in scope
      ├─ time-model.js          → tasks, runs, gaps, totals
      └─ five pages + detail panel render from those

The database is read once per load or poll and never queried per view — every page is a pure function of the in-memory row array. That keeps interaction instant and means a 50k-row file behaves the same as a 500-row one.

Deletions execute against the in-memory database as well as the row array; Save database copy exports the mutated bytes. The original file is never written to.

Libraries. sql.js 1.10.3 (CDN), React 18 (UMD), design-system bundle, time-model.js (local). Nothing else: no charting library, no date library, no icon package, no CSS framework. Bars, timelines and the waterfall are DOM elements with percentage widths; timestamps are handled with native Date; exports use Blob and an object URL.

If the page must run fully offline, vendor sql-wasm.js and sql-wasm.wasm next to the page and point the loader's locateFile at them — that is the only remote dependency.
