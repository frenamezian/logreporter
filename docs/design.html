Two voices, one vocabulary. Dark is system sans, 8px radii, and the accent used as a line, a tint or a glow — never as a flood. Light is Paper & Ink (Task 0010): ink text on a paper ground, hard corners everywhere, Archivo on the chrome titles, and two kinds of deliberately dark objects — the top bar and the stat tiles — so the page has more than one visual temperature. Every colour, size and space still comes from the tokens at the top of style.css.

Two themes, one vocabulary

The ☀ / ☾ button in the header switches between a near-neutral dark ground and the paper-and-ink light one. The choice is remembered in localStorage and applied before the first paint, so a reload never flashes the other theme.

Both themes define the same token names — only the values differ. That is the rule the stylesheet is built on: no colour literal may appear outside the two token blocks. A hex or an rgba() in a rule body is a value that can only be right in one theme, and it will be silently wrong in the other.

token         dark        light      used for
--bg          #0f1115     #f3f2f2    the page
--surface     #161821     #ffffff    cards, panels, code blocks
--surface-2   #1b1d2b     #eae8e7    inputs, buttons, table headers
--text        #e6e6e6     #201e1d
--text-dim    #9aa0b2     #6f6a67
--border      #2a2d3a     #c9c5c3
--accent      #5b8def     #0a72c4
--accent-2    #8eb6ff     #05537f    the accent used as TEXT — so it goes
                                     brighter on dark, darker on light
--radius  8px dark · 0 light   --font  system-ui …   --mono  ui-monospace …

The theme also carries the washes (--wash-1/2/3), hairlines, scrollbar, hatch, overlay and focus mark. Each exists because it was once a literal that only worked on a dark ground: a hover state is built by adding light on dark and by adding dark on light, so the two cannot share a value.

Since Task 0010 the vocabulary also carries a chrome-scoped set — --topbar-*, --tile-*, --mark-* and --stripe-*. In dark, every one of them equals the token it shadows, so those remappings change nothing there; in light they are what lets the top bar and the stat tiles stay dark objects on the paper page. Dark mode did change in exactly three sanctioned ways: the 5px category stripe under the header (drawn from --stripe-* in both themes), the brand mark's stem taking --brand (#ec3013, which shadows nothing — it is the one new colour), and the mark's corners going square.

The five categories

Five categories carry a fixed colour across every bar, dot, block and legend, and they never mean anything else. The meaning is fixed; the value is per-theme, because a hue chosen to sit on a near-black ground is not the hue that reads on paper:

Activity #4caf50 / #0d8442 Issue #f44336 / #e02d1b Decision #2196f3 / #3a5fe0 GitHub #4fc3f7 / #0099b0 Idle — hatched

Neither set was chosen by eye. Both are checked with seed/validate_palette.js for lightness band, chroma floor, colour-vision separation between adjacent pairs, and contrast against the ground — which is why the stacking order below is part of the guarantee rather than a preference. The light set clears all five checks; the dark set predates the validator and fails three, and is kept for continuity.

Idle is a diagonal hatch rather than a colour: absence should not read as another kind of work. start and end rows are drawn in the activity colour, because that is the category their time is attributed to.

Stacking order is always activity → issue → decision → GitHub → idle, on every bar at every level, so the same horizontal position means the same category everywhere.

The mark is built from the same parts

The letter L, with its foot built as a stacked category bar in the stacking order above. The letterform carries the name and the foot carries what the product does. Its corners are square, like every other corner in the brand.

The stem is the brand red (--brand, #ec3013 — the landing page's accent), in both themes. That superseded this mark's original "no red" rule in Task 0010, and the reservation that mattered survives it: red as an interaction or data colour still means an issue everywhere in the app; the mark sits on the chrome bar, where it reads as identity, and it is the only place the brand red appears. The foot still runs activity → decision → GitHub → idle, skipping the issue segment a logo would be dishonest to carry.

The mark is inlined in log-header.js rather than linked, and that is the whole reason it can exist as one file: its fills are var(--brand), var(--activity), var(--decision) and var(--github), so it re-colours itself on the ☀ / ☾ toggle like everything else. An <img> gets its own document, cannot see those tokens, and would have needed two files and a swap on every toggle. The idle segment uses --hatch-strong rather than --hatch, for the reason that token exists: at 28px a real diagonal hatch is noise and --hatch is invisible.

favicon.svg is the one deliberate exception to the no-literals rule. A tab icon is fetched as its own document and can never reach style.css, so it carries the brand red as a literal — one hex, legible on light and dark tab strips alike. It is also the reduced drawing — solid foot, no segments, strokes thickened from 5.6 to 7 — because below 24px the category splits merge into one muddy band. The silhouette is what survives at tab size, not the split.

Layout rules the pages share

  • One scroll region per page. The header, the breadcrumb strip, the sidebar and the detail panel are fixed; only the content region scrolls, so the columns you are reading against never leave the screen.
  • The detail panel is layout, not overlay. Opening it makes the content region narrower rather than covering it.
  • Identifiers are monospace and verbatim — repository, branch, agent name, agent_path, timestamps, trace ids. Closed enums (log type, level, status) are shown as written but styled as tags.
  • Selection is an accent left border plus a faint accent wash, never a colour change to the text.
  • Durations are always fmt() — "42s", "37m", "1h 31m" — and never raw milliseconds.
  • Counts are badges; issue counts are the only ones that carry the issue colour, so a red badge always means the same thing.
  • Empty is stated, not blank. Zero-value rows are dropped from distributions; missing fields read "—".

Two panels are resizable

The sidebar (default 320px, minimum 220px) and the detail panel (default 372px, minimum 280px) are both drag-resizable from their inner edge, capped at 60% of the window. Both widths live on LogApp.state and survive page switches.
