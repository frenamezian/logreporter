The five categories

Five categories carry a fixed colour across every bar, dot, block and legend, and they never mean anything else:

Activity #4caf50 Issue #f44336 Decision #2196f3 GitHub #4fc3f7 Idle — hatched

Idle is a diagonal hatch rather than a colour: absence should not read as another kind of work. start and end rows are drawn in the activity colour, because that is the category their time is attributed to.

Stacking order is always activity → issue → decision → GitHub → idle, on every bar at every level, so the same horizontal position means the same category everywhere.

Layout rules the pages share

  • One scroll region per page. The header, the breadcrumb strip, the sidebar and the detail panel are fixed; only the content region scrolls, so the columns you are reading against never leave the screen.
  • The detail panel is layout, not overlay. Opening it makes the content region narrower rather than covering it.
  • Identifiers are monospace and verbatim — repository, branch, agent name, agent_path, timestamps, trace ids. Closed enums (log type, level, status) are shown as written but styled as tags.
  • Selection is an accent left border plus a faint accent wash, never a colour change to the text.
  • Durations are always fmt() — "42s", "37m", "1h 31m" — and never raw milliseconds.
  • Counts are badges; issue counts are the only ones that carry the issue colour, so a red badge always means the same thing.
  • Empty is stated, not blank. Zero-value rows are dropped from distributions; missing fields read "—".

Two panels are resizable

The sidebar (default 320px, minimum 220px) and the detail panel (default 372px, minimum 280px) are both drag-resizable from their inner edge, capped at 60% of the window. Both widths live on LogApp.state and survive page switches.
