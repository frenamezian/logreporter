System sans, 8px radii, and the accent used as a line, a tint or a glow — never as a flood. Every colour, size and space comes from the tokens at the top of style.css.

Two themes, one vocabulary

The ☀ / ☾ button in the header switches between a near-neutral dark ground and a warm high-summer light one. The choice is remembered in localStorage and applied before the first paint, so a reload never flashes the other theme.

Both themes define the same token names — only the values differ. That is the rule the stylesheet is built on: no colour literal may appear outside the two token blocks. A hex or an rgba() in a rule body is a value that can only be right in one theme, and it will be silently wrong in the other.

token         dark        light      used for
--bg          #0f1115     #fffaf2    the page
--surface     #161821     #ffffff    cards, panels, code blocks
--surface-2   #1b1d2b     #fdeedb    inputs, buttons, table headers
--text        #e6e6e6     #33261c
--text-dim    #9aa0b2     #785c45
--border      #2a2d3a     #f0dcc2
--accent      #5b8def     #0a72c4
--accent-2    #8eb6ff     #05537f    the accent used as TEXT — so it goes
                                     brighter on dark, darker on light
--radius  8px   --font  system-ui …   --mono  ui-monospace …

The theme also carries the washes (--wash-1/2/3), hairlines, scrollbar, hatch, overlay and focus mark. Each exists because it was once a literal that only worked on a dark ground: a hover state is built by adding light on dark and by adding dark on light, so the two cannot share a value.

The five categories

Five categories carry a fixed colour across every bar, dot, block and legend, and they never mean anything else. The meaning is fixed; the value is per-theme, because a hue chosen to sit on a near-black ground is not the hue that reads on sand:

Activity #4caf50 / #0d8442 Issue #f44336 / #e02d1b Decision #2196f3 / #3a5fe0 GitHub #4fc3f7 / #0099b0 Idle — hatched

Neither set was chosen by eye. Both are checked with scripts/validate_palette.js for lightness band, chroma floor, colour-vision separation between adjacent pairs, and contrast against the ground — which is why the stacking order below is part of the guarantee rather than a preference. The light set clears all five checks; the dark set predates the validator and fails three, and is kept for continuity.

Idle is a diagonal hatch rather than a colour: absence should not read as another kind of work. start and end rows are drawn in the activity colour, because that is the category their time is attributed to.

Stacking order is always activity → issue → decision → GitHub → idle, on every bar at every level, so the same horizontal position means the same category everywhere.

Layout rules the pages share

  • One scroll region per page. The header, the breadcrumb strip, the sidebar and the detail panel are fixed; only the content region scrolls, so the columns you are reading against never leave the screen.
  • The detail panel is layout, not overlay. Opening it makes the content region narrower rather than covering it.
  • Identifiers are monospace and verbatim — repository, branch, agent name, agent_path, timestamps, trace ids. Closed enums (log type, level, status) are shown as written but styled as tags.
  • Selection is an accent left border plus a faint accent wash, never a colour change to the text.
  • Durations are always fmt() — "42s", "37m", "1h 31m" — and never raw milliseconds.
  • Counts are badges; issue counts are the only ones that carry the issue colour, so a red badge always means the same thing.
  • Empty is stated, not blank. Zero-value rows are dropped from distributions; missing fields read "—".

Two panels are resizable

The sidebar (default 320px, minimum 220px) and the detail panel (default 372px, minimum 280px) are both drag-resizable from their inner edge, capped at 60% of the window. Both widths live on LogApp.state and survive page switches.
