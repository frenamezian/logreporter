What each block counts

  • Cards — tasks by state (open = pending or in progress; a task with no closing end row counts as open), and total idle time as a duration.
  • Entries by log type — raw row counts over the rows in scope, largest first, each bar in its category colour. start and end appear as their own types here, unlike in the time bars where their time is attributed to activity.
  • GitHub operations — github rows bucketed by the action found in tags and log_title: pull, push, commit, add, delete. Rows matching none of them are dropped rather than bucketed as "other".
  • Median task duration — the median of the tasks' wall-clock times per repository. Median, not mean, because one abandoned task that ran overnight otherwise dominates.
  • Open issues — log_type === 'issue' with no resolved_by, in scope order.
  • Agent time — summed run spans per agent_path, the twelve largest, with the number of runs. Nested paths appear separately and overlap by design.

Bars are scaled against the largest value in view, not a fixed maximum, so a distribution stays legible whether the scope holds 40 rows or 40,000. Zero-count rows are dropped rather than drawn empty.

ElementBehaviour
Tokens ⇄ CostRedraws the same layout against one measure. Ordering, colour and layout hold across the switch; only the values change. Never a shared axis.
Ranking rowsOrdered by tokens in both views, so rows do not jump on toggle. The cost view is therefore not always descending — that disagreement is the point of the toggle.
Ranking colourSequential: one hue in five steps, dim→bright. A dark surface inverts "more is darker" — a darker bar would recede exactly where the value is largest. The step follows the value's share of the maximum, not the row index, so a filter that drops the largest row does not repaint the survivors.
Segment colourIts own validated four-step ramp. --activity, --issue, --decision and --github are reserved for log types: a cost bar in the issue red would read as an error.
UnattributedHatched and italic so it never reads as a task, but ranked on its value like any other row.
TableSortable on every column, nulls last in both directions, capped at 500 rows with the cap stated on screen.
Empty statesNo cache yet, unreachable, unreadable and "no rows match" are four different messages. The first tells you how to build it.

The ramps are validated, not chosen by eye:

     --mode dark --surface "#161821" --ordinal

Both pass every gate against this project's own surface. The order is the safety mechanism, not decoration: orange next to amber measures ΔE 4.8 under deuteranopia and 10.6 with full colour vision, which fails both floors — putting magenta and violet between them is what makes the set legible. If you re-order these, re-run the validator.
