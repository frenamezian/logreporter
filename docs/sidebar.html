The left panel holds two collapsible sections — Filters and Navigation — and between them they decide what every page is looking at. Filters choose which rows exist; navigation chooses which part of them you are standing in.

Filters

The top header bar carries the collapsible Filters label with its active filter count pill and the « sidebar collapse button. Inside the filter section, every filter is ANDed with the others. There are four kinds:

  • Hour range slider — sitting right at the top of the panel, this dual-handle slider filters activities by relative age from Now (0h) on the left to 48h on the right: [Now, 1h, 3h, 6h, 12h, 24h, 48h].
    • The left handle sets the recent boundary (e.g. Now or 1h ago).
    • The right handle sets the past boundary (e.g. 6h ago or 12h ago).
    • Setting Now → 6h shows the last 6 hours (badge: Last 6h). Moving the left handle to 1h or 3h isolates a historical slice (e.g. badge: 3h–6h), strictly excluding recent activity.
    • Default is Last 6h; your selection is automatically remembered in localStorage across page reloads. Clicking the badge toggles the filter on or off (All).
  • Search — always visible below the chips. Type freely and press Enter to apply; Escape clears it. It matches log_title, log_description, agent_name and agent_path, case-insensitively. It deliberately does not apply per keystroke — half a word would narrow the whole dashboard to nothing while you were still typing it.
  • Eight multi-selects — Repository, Branch, Agent, Log type, Git action, Level, Status, Priority. Each is a checkbox list: tick several values and they are ORed within that filter. Only one list is open at a time and clicking outside closes it. The button shows the count, and the line under it summarises the first three choices.
  • From / To — an inclusive calendar date range, applied as you pick.

Two of the lists are not simply "every value in the file". Branch is scoped to the repositories you have selected, because branch names repeat across repositories and an unscoped list is unusable. Agent lists full agent_path values but matches either the path or the bare agent name, so picking a subagent finds its rows wherever it ran.

Every active value (including the hour window, e.g. Last 6h ✕ or 3h–6h ✕) gets a chip above the search box; clicking a chip removes that one value. Clear all next to the hour slider removes all filter selections and deactivates the hour constraint (All), and the pill next to the word Filters in the top header bar counts what is active even when the section is collapsed.

Changing any filter clears the drill scope and closes the detail panel — the row you had open may no longer be in scope, and a stale drill into a task the filter just excluded shows an empty page.

Navigation

The tree is repository → branch → task → agent, and the agent level is nested from agent_path, so a subagent appears underneath the agent that spawned it. Repositories and branches show their wall-clock time; tasks and agents show a row count. Each task also carries the date of its last log, on the left of its title:

▾ logreporter                                 7h 46m
  ▾ restyle/task-0010-paper-ink               3h 53m
    ▾ 07/aug  Task 0010: Paper & Ink restyle…     26
      ▸        lead_architect                     26
  ▸ main                                      2h 51m

Sort tasks, above the tree, switches between Recent — the most recent last log first, which is what the tree has always done — and Name, the task title A→Z with numbers in numeric order, so task_0009 precedes task_0010. The setting drives the Hierarchy page's tree as well: two trees ordering the same tasks differently is worse than either order on its own.

The date is the value the default sort runs on, which is the point of showing it — an order you can see the key for is an order you can trust. It is written dd/mon, with the year appended when it is not the current one, and in UTC, like every other timestamp in the app. Hovering a task gives its full title and the exact time of that last log.

If a task expands into something that looks like a directory listing — projects → docs → tasks → a filename — that is not a display fault. An agent has written a file path into agent_path, and the tree is faithfully showing every segment as an agent. The fix is in that agent's prompt, not here: agent_path is a lineage of agents, and the file being worked on belongs in log_title or log_description.

Click a nodeDrills the whole dashboard to it and opens it. The breadcrumb above the content follows, and the node is highlighted.

Click an agentDrills to that agent within its task; clicking it again drops back to the task. A row is in scope when the agent's name appears anywhere in its agent_path, so drilling to a parent keeps its subagents' rows.

The tree is built from the filtered rows before the drill is applied. That is deliberate: every sibling stays visible and one click away, so moving from one task to its neighbour never requires walking back up the breadcrumb first.

Width and collapsing

Drag the panel's right edge to resize it (220px minimum, 60% of the window maximum). The « button collapses it to a narrow rail carrying a gear icon and a badge with the number of active filters; clicking that icon restores the panel with the filter section open.

On the Help page

Filters have nothing to narrow here, so the same panel carries this guide's outline instead. The field at its top searches the whole guide — headings and prose alike. Topics that match only in the body are marked in text, the line under the field says how many of the topics matched, and Escape or Clear restores the full outline. The rail's icon becomes ☰ and brings the outline back.
