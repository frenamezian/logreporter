Logs are retained until you delete them — there is no automatic rotation, on purpose. This page is where you look at what is stored, remove some of it, or carve a slice out as a file.

The scope trail

The pills at the top — All repos › Repo › Branch › Task › Agent — are the current drill, restated in full because every count on this page is a count of it. Clicking a pill drills back to that level; See all repos clears the drill entirely, which also deselects the node in the navigation tree.

Delete

Deletion uses the same filters and drill scope as the left panel. The active filters are restated as read-only chips so nothing is hidden, and Older than is the one delete-specific refinement: it further narrows the selection to rows before that date.

The line above the button always says what will go — "25 of 189 logs match in 1 repository" — and the button repeats the count. Pressing it opens a confirmation restating the number of rows and how many repositories they touch; nothing is removed until you confirm.

Where the rows actually go. When the page is served by serve.py, the confirmed delete is posted to that server, which removes the rows from activity_logs.db itself and checkpoints the write-ahead log; the page then re-reads the database, so what you see is what is stored. The header note reports how many rows were deleted and how many remain.

Two cases behave differently, and say so:

  • Demo data — there is no file to write to, so the delete only affects the copy in memory. The note says "removed in memory".
  • Served without serve.py (plain http.server, or opened over file://) — the delete endpoint does not exist. The rows are removed from the in-memory copy so the view still responds, and the note turns red: NOT saved to the database — start the app with start_LogReporter.bat. Refreshing brings them all back.

Export

Export CSV and Export JSON write the rows in the current filter and drill scope — the same rows the header's CSV and JSON buttons write. Save database copy downloads the in-memory database as a .db file; it never overwrites the file you opened.

Total log count

The table below breaks the rows in scope down by the level just under the drill, so drilling one step always answers "and what is that count made of?". At the top it groups by repository; inside a repository, by branch; inside a branch, by task; inside a task, by agent_path, which is the floor.

Columns above the grouping level repeat the scope's value; columns below it read All, because the row aggregates every value they could take. Each row carries its log and issue counts and its oldest and newest timestamps — enough to judge what is worth pruning.
