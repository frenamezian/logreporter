The LLM registry as a rate card. Every model LogReporter knows how to price, what each one costs per million tokens, and every pricing tier behind those headline numbers. This is the only page in the app that does not read your logs at all — it reads script/llm_registry.js, the same file the Metrics page prices your token usage against.

Three levels, because 102 models is not a table

The registry holds 102 models across eight providers. Nobody reads that as one list, so the page opens in stages:

  • A closed provider panel carries its model count, a status breakdown and its price range. The range is the point — it is what tells you which panel is worth opening.
  • An open panel shows the prices you actually compare on: standard and cache, input and output, one row per model.
  • An open model row shows the description, the specifications, and every remaining tier — batch, flex, priority, long-context, fast mode.

Provider panels and model rows remember what you opened. A background poll or a filter change never collapses them.

The columns follow each provider's own vocabulary

Providers disagree about what a cache is called. Anthropic prices cache_read and two cache_write retentions; OpenAI, xAI, Moonshot, DeepSeek and Zhipu price cached_input; Google prices context_cache. Because the table lives inside a provider panel, its columns can use that provider's own tier names instead of a normalised label that matches nobody.

So the column set differs by panel, and that is deliberate:

ProviderPrice columns
Anthropicstd · cache read · cache write 5m/1h · std (out)
OpenAI, Google, xAIstd · cached input · std (out) · batch (out)
Mistralstd · std (out) — no Mistral model prices a cache tier, so no cache column is drawn

Four price columns is the ceiling. Past that the model id starts getting truncated, and everything else is one click away.

There is no cached-output column, and there never will be. No provider in the registry prices cached output — caching is an input-side concept. A fourth quadrant would have been permanently empty, so the grid is three columns and one, and the asymmetry is stated in the tier panel rather than drawn as a blank.

An em dash is never a zero

A dash means the provider does not sell that tier for that model. It is not $0.00, and the distinction matters in both directions:

  • gpt-5.5-pro has no cached input at all — its cache cell is a dash.
  • Four models in the registry are genuinely free and show $0 — labs-leanstral-1-5 at the standard rate, and Gemma 3, Gemma 3n and GLM-4.7-Flash on a free tier. That zero has to keep meaning zero.
  • Nineteen models have no standard tier: the realtime family is priced per modality, and the retired deep-research models were batch-only. Their headline row is all dashes, so the row carries a line saying what it is priced by — "no standard tier — priced by audio $32.00, text $4.00 in · audio $64.00, text $24.00 out" — instead of leaving you to open it and guess.

Launch prices are shown as the price you pay

A tier named intro_…_until_YYYY_MM_DD is a launch price with an end date, and it displaces the standard rate until that date passes. Claude Sonnet 5 has one: its stored standard is $3.00 / $15.00, but nobody pays that before 1 September 2026. The headline cell shows the rate in force today with an intro marker, and the marker's tooltip names both the end date and the price that follows it. The tier panel lists the intro tier with an in force or expired tag.

This is the same rule the cost model applies when pricing your actual usage, so a session dated inside the window costs at the introductory rate and one after it does not.

The tier panel

The registry stores input and output tiers as two independent lists, but their names overlap heavily. Joining them on the tier name turns nine scattered numbers into six comparable lines, and makes visible at a glance what the headline cannot: batch is −50% both ways, cache read is −90%, fast mode is +100%.

The percentage is measured against that direction's standard rate, and each direction has its own column, because the two do not always agree — gpt-5.4's long-context tier is +100% on input and +50% on output. One shared column would have had to pick one of those and be wrong about the other.

Filters and the retired models

The sidebar filters the registry, not your logs: provider, status, capability, context window, a free-text search over name, id and description, and the sort order. Search matches on every keystroke and opens any provider that has a hit, for as long as the search is active.

Legacy and deprecated models are hidden by default. Thirty-seven of the 102 are retired, and they are kept in the registry for one reason: a six-month-old session has to price at what it actually cost. They are not something to shop from. Each provider panel says how many it is hiding and offers a one-click show every status; a deprecated model that is still listed carries its retirement date on the row.

This page is a rate card, not a bill. It reports the provider's published API prices. What your agents actually spent is on the Metrics page, which prices real token counts against this same registry. If a model here looks wrong, the fix is to regenerate the registry — see Agent logging prompts for the update prompt — not to edit a number in the dashboard.
