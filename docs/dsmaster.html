State that lives in the shell

All of it hangs off LogApp.state, so a component re-render never loses it: page, filter, drill, selectedLog, selectedRun, order, taskOrder, helpTopic, sidebar / panels, navOpen and treeOpen (two independent expand sets), sidebarWidth / detailWidth, and the search draft.

taskOrder is shared rather than per-tree on purpose: the sidebar and the Hierarchy page list the same tasks, and two orders for one set of rows is a worse answer than either order alone.

Four more keys carry the refresh baseline — refreshBaseIds (a Set of row ids), refreshBaseAt, refreshBaseLabel and the refreshStats diff cut against them. The baseline moves only on a deliberate act: an explicit Refresh, page load, or a different database being opened. A poll tick recuts the diff and leaves the baseline alone, which is what lets the count accumulate between refreshes instead of being swallowed five seconds after each row lands.

Three pieces of state answer to something other than the logs. measure is the Tokens ⇄ Cost toggle, shared by Metrics and Where time goes so the two never disagree about which measure is on screen. modelsFilter, modelsOpen and modelRowOpen belong to the Models page, which filters the price registry rather than the logs. And usage / usageReport hold the second database — loaded after the first render, deliberately, because the log file is what the page is actually about and the usage cache can be tens of megabytes.

The sidebar slot follows the page rather than the app: filters normally, the guide's outline on Help, the registry's facets on Models. All three are the same 320px column with the same collapse behaviour.

What clicking does, shell-wide

  • A page tab — swaps the content region only. Filters, drill, both expand sets and the open entry all survive; switching pages is a change of lens, never a reset. Maintenance, Models and Help close the detail panel, because none of them has entries to keep it in sync with.
  • A tree node — drills and opens; clicking the node you are already on collapses it. Double click always collapses. An agent node toggles between the agent and its task.
  • A breadcrumb — truncates the drill to that depth. All repos clears it. The drill trail is suppressed on Help and Models, which have no log scope — Models shows its provider facet in the same slot instead, because that is the same kind of narrowing.
  • A filter or chip — recomputes the scope, clears the drill and closes the panel; the header count and every page follow in the same frame.
  • Any entry row, anywhere — selects it and opens the detail panel. The content region reflows narrower rather than being overlaid. Clicking a blank part of the content region closes it again.
  • The « button — collapses the left panel to a 46px rail carrying a gear icon and the active-filter badge; the icon restores the panel with filters open. On Help the rail carries ☰ instead.
  • Either resize handle — drags the sidebar's right edge or the panel's left edge. Both are clamped: 220px / 280px minimum, 60vw maximum.
  • ? — opens the Help page. It is a page like any other; the tab you came from is one click away.

The sponsor strip

A band across the bottom, spanning the full width under every column. Its height is clamp(48px, 9vh, 88px) — proportional to the window, capped so it can never take more than a tenth of a realistic viewport, floored so the banner stays legible on a short one.

It is the one element that lives outside <app-shell>, and the one component that does not extend LogComponent. Both for the same reason: the shell rewrites its innerHTML on every render and LogComponent re-renders on every logapp:update, so either would restart the rotation and re-request the images every time a filter moved. It renders once, owns its own timer and never reads application state. Rotation pauses on hover, on focus, and while the tab is hidden.

The ads are data: docs/lespirant/ads.json lists them. Delete that file and the strip degrades to a single text credit; empty its ads array and it does the same. No code changes either way.

Scrolling

Exactly one element scrolls: the content region (.page-host). The header, breadcrumb strip and legend rows are fixed. The sidebar and the detail panel scroll independently within themselves. Selecting a new help topic resets the content scroll to the top — but only on a genuine topic change, never on a poll tick, which would otherwise yank the page out from under whoever is reading it.
