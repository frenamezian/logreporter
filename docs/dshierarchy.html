The right-hand summary is, in order: a count and the wall-clock total (plus the idle share when there is any), the stacked bar scaled to that row's own wall clock, the log and issue badges, and Time →.

Click targetResult
A repository, branch or task rowToggles it open or closed by patching the DOM in place — no app re-render, so scroll position is kept and the element survives between the two clicks of a double click.
Double click, any levelAlways ends collapsed.
Time →Sets the drill scope to that repository, branch or task and switches to Where time goes. The one cross-page jump on this page; it stops propagation so it never toggles the row it sits in.
Entry rowSelects the entry and opens the detail panel. The five-column grid stays — the content region reflows and the columns absorb it.
Panel ×, or a blank part of the pageCloses the panel.
Expand allOpens every repo, branch and task holding a row in the current scope — not the whole database.
Collapse allClears this page's expand set. The navigation tree keeps its own, independent set.

Implementation notes

  • The page renders from state.model (drill applied), so it stays consistent with every other page. The sidebar tree renders from state.treeModel (drill not applied), which is why siblings remain visible there.
  • Entry rows are built lazily the first time a task is opened, and wired at that moment — a file with thousands of rows still expands instantly.
  • Drilling auto-expands the path once, keyed on the drill itself. Re-applying it every render would fight the user: a row collapsed by hand would spring back open on the next poll tick.
  • Entries inside a task sort ascending — you read a task the way it happened — while repositories, branches and tasks keep the model's ordering (longest wall clock, then most recently ended).
