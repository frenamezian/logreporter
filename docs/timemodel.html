Durations are never stored — they are derived, in time-model.js, so that any log file produces the same numbers.

  • Run — one start→end pair for one agent_path within one task. Its length is the run's agent time.
  • Segments — the entries inside a run split it into consecutive slices, each attributed to the log type that opened it: activity, issue, decision or github. That is what colours every stacked bar.
  • Wall-clock — first to last event of the task, regardless of who was working.
  • Idle — the complement of the union of all runs inside that wall-clock span. Overlapping agents are unioned first, so parallel work never manufactures idle time.
  • Agent time — the sum of run lengths. It can exceed wall-clock when agents overlap; that ratio is shown on the stat card.

Branch, repository and global totals are sums of task totals, so an idle share is always comparable across levels. The largest gap per task is kept separately for the waterfall callout and the gaps table.

Consequences worth knowing: a run whose end row never arrived contributes no time; a task with a single entry has zero wall-clock; and time spent by a process that logs nothing counts as idle, which is the honest reading.
