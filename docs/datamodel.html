One table, logs, one row per event. Nothing is normalised away: repository, branch, task and agent identity live on every row so a single append is always sufficient.

ColumnTypeNotes
idINTEGER PKAutoincrement.
timestampTEXTYYYY-MM-DD HH:MM:SS, UTC. Sorts lexically.
repo_name / branch_nameTEXTVerbatim identifiers, never humanised in the UI.
task_titleTEXTThe unit of work. Empty rows group as "Untitled task".
log_typeTEXTstart · end · activity · issue · decision · github
log_titleTEXTOne line, imperative or past-tense. Shown in every list.
log_descriptionTEXTThe prose. Snippets are truncated in lists, full text in the panel.
log_levelTEXTdebug · info · warning · error
statusTEXTpending · in_progress · failed · completed
priorityTEXTlow · medium · high · critical
agent_nameTEXTThe agent that wrote the row.
agent_pathTEXTSlash-delimited lineage, e.g. lead_architect/handler_dev. Depth drives indentation.
trace_id / parent_trace_idTEXTShared by every row of one multi-agent run; the parent links a spawned run to its caller.
user_idTEXTWho or what initiated the work.
tagsTEXTComma-separated #hash tokens. On a github log one tag is the git action.
error_detailsTEXTRaw exception or stderr. Rendered monospace, unmodified.
resolved_by / resolution_timeTEXTSet when a later step closes out an issue.
performance_metricsTEXT (JSON)execution_ms, tokens, cpu_pct, memory_mb — all optional.
input_output_hashTEXTOptional fingerprint for deduplication and replay.

The one hard invariant: each agent brackets its work with a start row and an end row carrying the same repo, branch, task and agent_path. Durations and idle gaps are derived from those pairs; without them a run has no span and contributes no time.
