One table, logs, one row per event. Nothing is normalised away: repository, branch, task and agent identity live on every row, so a single append is always sufficient and no writer ever has to read before it writes.

The three keys everything is built on

  • (repo_name, branch_name, task_title) groups rows into a task. Character for character — a task title that drifts by one space becomes two tasks with two separate wall clocks.
  • agent_path groups rows within a task into runs, and its / depth defines the parent-child relationship the waterfall indents and "own time" corrects for.
  • trace_id links rows into one narrative for the detail panel's trace timeline. It is the only key that is allowed to cross tasks.
The one hard invariant: each agent brackets its work with a start row and an end row carrying the same repo, branch, task and agent_path. Every duration and every idle gap is derived from those pairs. A run whose end never arrived is closed at its last event, so the work after that point simply disappears from the time views.

Indexes

The shipped file has none, which is fine at this size — the dashboard issues one unindexed full scan per load. On a large file, (timestamp) helps the read and (repo_name, branch_name, task_title) helps any grouped query you run against the file directly.
