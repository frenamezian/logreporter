Counts and distributions over the same filter and drill scope as every other page — nothing here is computed over the whole database unless the scope is the whole database.

The four cards

Task counts by state — Open (pending or in progress), Completed, Failed — and total Idle time. A task's state is the status on its last end row; a task with no closing row at all counts as open.

Left column — distributions

  • Entries by log type — how many rows of each type are in scope, largest first, each in its category colour.
  • GitHub operations — github rows broken down by git action. The action is read from the row's tags and title: pull, push, commit, add, delete. Rows with no recognisable action are left out rather than bucketed as "other".
  • Median task duration by repository — the median of the tasks' wall-clock times. Median, not mean, because one abandoned task that ran overnight otherwise dominates the number.

Bars are scaled against the largest value currently in view, not a fixed maximum, so a distribution stays legible whether the scope holds forty rows or forty thousand. Empty categories are dropped rather than drawn as zero-width bars.

Right column — what needs a person

  • Open issues and escalations — every issue row in scope with no resolved_by set, as cards carrying the repository and branch, the title, the description and the level. Clicking a card is the one deep link on this page: it switches to Hierarchy, expands the repository, branch and task around that row, and opens it in the detail panel.
  • Agent time — total run span per agent_path, the twelve largest, with the number of runs alongside. A nested path is listed on its own line, so a parent and its subagent both appear and their times overlap by design — see Where time goes for why.
Everything on this page is read-only. It reports the scope; it never sets it. Drill to a branch and "median task duration by repository" shows exactly one row — that is correct, not a bug.
