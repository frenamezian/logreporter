Clicking any entry — a hierarchy row, a chronology row, a waterfall block, a run-log row or a metrics issue card — opens the detail panel on the right. It is part of the layout, not an overlay: the page beside it reflows narrower rather than being covered.

What it shows, top to bottom

  • Prev / Next in trace — the trace walk, kept at the top so it is reachable without scrolling the panel.
  • Type badge and title, then the task the entry belongs to.
  • Description in full — lists elsewhere truncate it, this never does.
  • Tags, split on commas and spaces.
  • Error details — the raw error text, monospace and unmodified, when the row carries any. It is pulled out of the record grid because it is usually the reason you opened the entry.
  • Agent path — the lineage as an indented chain from the root agent down to the one that wrote the row.
  • Record — every stored field verbatim, including timestamp, trace and parent trace, status, priority, user, resolution fields, performance_metrics and the input/output hash. Empty fields read "—" rather than disappearing, so you can tell "not set" from "not shown".
  • Trace timeline — every entry sharing this trace_id, each with its offset from the first one, so a multi-agent run reads as a single sequence. Clicking a line jumps to that entry.

Traces cross tasks on purpose

The trace list is built from the filtered rows, before the drill scope is applied. A trace is one run of work and can span more than one task; cutting it at the drill boundary would hide half the story. If Next in trace steps into another task, the dashboard follows — the drill moves with it, so the waterfall behind the panel keeps showing the entry that is open.

Closing and resizing

The × closes the panel, and so does clicking an empty part of the page behind it. Drag the panel's left edge to resize it — 280px minimum, 60% of the window maximum. Switching to Maintenance or Help closes it, since neither page has entries to keep it in sync with.
