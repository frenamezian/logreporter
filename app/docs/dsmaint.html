One scope, stated three times

Delete and export both use the page's filter and drill scope — the same rows every other page is showing. That was a deliberate reversal of an earlier design where delete carried its own hidden scope: two scoping rules on one page meant the count under the button never matched the count in the header. Now the scope trail restates the drill as pills, the delete card restates the active filters as read-only chips, and the volume table counts exactly that. Older than is the single delete-only refinement.

Click targetResult
A scope pillDrills to that level. See all repos clears the drill, which also deselects the node in the navigation tree — that highlight is driven by the drill state.
Older thanRecomputes the match count immediately; the card re-renders on its own without touching the rest of the app.
Delete N logsOpens the confirmation restating the count and how many repositories it touches. Nothing is removed yet. The backdrop or Cancel dismisses it.
ConfirmPOSTs the ids to serve.py, which deletes them from activity_logs.db and checkpoints the WAL; the page then re-reads the database so the screen matches the file. On demo data, or when the endpoint is missing, it falls back to the in-memory copy and says so — in the second case in red, because a refresh will bring the rows straight back.
Export CSV / JSONWrites the rows in scope, columns verbatim — identical to the header's CSV and JSON buttons.
Save database copyDownloads the in-memory database bytes. It never overwrites the file that was opened.

The volume table

It groups by the level just below the deepest drilled one — repo → branch → task → agent_path, which is the floor — so drilling one step always answers "and what is that count made of?". Columns above the grouping level repeat the scope's value; columns below it read All, because the row aggregates every value they could take. Groups are sorted by row count, and each carries its issue count and its oldest and newest timestamps.
